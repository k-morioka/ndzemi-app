0演習の目的

自然言語(ふだんの日本語)でAIに指示して、Webアプリを制作します。
今回は、プログラムを自分で一から書くことよりも、 AIへの指示と動作確認・改良を重視します。

補足: プログラミングの進化

プログラムを書く方法は、機械語、アセンブリ言語、高級言語へと、人が分かりやすく書ける形に変わってきました。今は生成AIに、ふだんの言葉で作りたいものを伝える方法もあります。

どの方法でも、コンピューターが最後に実行するのは機械語です。AIに作ってもらったプログラムも、自分で動かして、思いどおりか確かめることが大切です。

この演習で身につけたいこと

① 指示する何を作りたいかを言葉で伝える
→
② AIが作るAIがファイルを作成・編集する
→
③ 動かして確かめるブラウザで実際に操作する
→
④ 気づいたことを伝える不具合・改善点を具体的に

この①〜④を何度も繰り返して、アプリを少しずつ良くしていきます。

Claude Code 以外の似たツール

この演習では Claude Code を使いますが、AI に指示してプログラムを作ってもらうツールはほかにもあります。例えば次のようなものです。

CodexOpenAI(ChatGPT の会社)のツール。Claude Code と同じように、ターミナルや VS Code から使えます。
GitHub CopilotGitHub のツール。VS Code に組み込まれていて、チャットで指示してファイルを編集してもらうこともできます。
Gemini CLIGoogle のツール。ターミナルから Gemini に指示して作業してもらえます。
CursorAI の機能を中心に作られた、VS Code に似たエディター。

どれも「言葉で指示する → AI が作る → 動かして確かめる → 直してもらう」という使い方は共通です。この演習で身につけた指示の出し方や確かめ方は、ほかのツールでもそのまま役に立ちます。

ここに挙げたのは一例です。この分野は変化が速く、ツールの機能や料金はよく変わります。ほかのツールを使ってみたいときは、公式の案内などで自分で調べて確かめてください。

心がけてほしいこと

  • AIは間違えることがあります。「できました」と言われても、必ず自分で動かして確認しましょう。
  • コードを全部理解する必要はありませんが、AIが何をしたのか説明を読む習慣をつけましょう。分からなければAIに質問してかまいません。
  • 個人情報・パスワード・他人の作品などをAIに入力しないでください。
作例: このフォルダの game(ブロックス) も、 Claude Code への日本語の指示だけで作りました。 「まずはシンプルなものから」と頼み、遊びながら「CPU対戦にしたい」「表示が縦長になる」などと改良を重ねています。

1Claude Codeの準備

VS Code(エディター)に Claude Code の拡張機能を入れ、メイジメールに届いた招待リンクから参加したアカウントでログインします。

  1. メイジメールで招待リンクを確認する

    Claude Code を使うための Anthropic Console(Claude Platform)への招待リンクは、Anthropic からの自動送信、または教員からの招待メールで、皆さんのメイジメール(大学のメールアドレス)に届きます。 メイジメールで招待メールを探し、記載されたリンクを開いて招待を受け入れてください。

    見つからないときは迷惑メールフォルダも確認してください。

  2. VS Code を用意する

    まだ入っていない場合は code.visualstudio.com からダウンロードしてインストールします。

  3. Claude Code 拡張機能をインストールする

    VS Code の左側にある拡張機能アイコン(四角が4つのマーク)をクリックするか、Ctrl+Shift+X を押します。 検索欄に Claude Code と入力し、「Claude Code for VS Code」(発行元: Anthropic ✔ anthropic.com)を選んで「インストール」を押します。

    「Chat for Claude Code」「Claude Code Assistant」など、似た名前の別の拡張機能が並んでいます。発行元が Anthropic であることを必ず確認してください。

  4. Claude Code を開く

    エディター右上に表示されるオレンジ色の ✳ アイコンをクリックすると、Claude Code の画面が開きます。 画面右下のステータスバーにある「✳ Claude Code」からも開けます。 見つからない場合は Ctrl+Shift+P でコマンドパレットを開き、Claude Code と入力して表示されるコマンドから開きます。

  5. ログイン方法で「Anthropic Console」を選ぶ

    初回は「How do you want to log in?」(どの方法でログインしますか?)と聞かれます。 真ん中の「Anthropic Console」をクリックします。

    一番上のオレンジ色の「Claude.ai Subscription」は、個人で Claude の有料プランに入っている人向けです。この演習では選ばないでください。「Bedrock, Foundry, or Vertex」も選びません。
    Claude Code の画面は英語で表示されます。分からない表示があっても、この手順書のとおりに進めれば大丈夫です。

  6. ブラウザでメイジメールのアカウントで認証する

    「Code で外部の Web サイトを開きますか?」という確認が出たら「開く」を押します。ブラウザで Anthropic Console(platform.claude.com)のログイン画面が開くので、 招待リンクを案内されたメイジメールのアドレスでログインし、画面の指示に従って許可してください。 確認用のメールが届いた場合は、メイジメールで開いて手続きを進めます。

    認証が終わったら VS Code に戻ります。自動でチャット画面に切り替わらない場合は、ブラウザに表示された認証コードをコピーし、 VS Code の「Or, paste your authorization code manually」の欄に貼り付けて「Continue」を押します。

    ブラウザが開かなかったときは、「If the browser didn't open, visit this URL」の欄の右にあるボタンで URL をコピーし、ブラウザに貼り付けて開きます。
うまくいかないとき
  • 招待の案内が見つからない: メイジメールの迷惑メールフォルダを確認してください。それでも見つからなければ教員に連絡してください。
  • ログインできない: 招待リンクを開いて招待を受け入れたか、メイジメールのアドレスでログインしているか(個人のメールアドレスになっていないか)を確認してください。ログイン方法で「Claude.ai Subscription」を選んでしまった場合は、Claude Code のチャット欄で /logout と送ってログアウトし、「Anthropic Console」でログインし直してください。
  • アイコンが出ない: VS Code を再起動してみてください。拡張機能がインストール済みになっているかも確認しましょう。
  • それでも解決しないときは、表示されているメッセージを控えて教員に相談してください。

2最初のWebアプリを作る

作業用のフォルダを作り、Claude Code の設定を確認してから最初の指示を出し、ブラウザで動かすところまで進めます。

  1. 作業用フォルダを作る

    エクスプローラー(Mac は Finder)で、アプリ用の新しいフォルダを作ります。例: ドキュメント\webapp\my-first-app

    フォルダ名は半角英数字とハイフン(例: my-first-app)にしておくと、後で公開するときに困りません。

  2. VS Code でフォルダを開く

    VS Code のメニューから ファイル → フォルダーを開く を選び、作ったフォルダを開きます。

    Claude Code は開いているフォルダの中で作業します。必ず作業用フォルダを開いてから指示を出しましょう。

  3. フォルダを「信頼する」

    「このフォルダー内のファイルの作成者を信頼しますか?」と聞かれたら、自分で作ったフォルダなので「信頼する」を選びます。

    画面上部に「制限モードは、安全なコード参照のためのものです…」という帯が出ている場合は、まだ信頼されていません。 帯の「管理」をクリックし、表示された画面で「信頼する」を押してください。

    制限モードのままだと、Claude Code などの拡張機能が使えなかったり、機能が制限されたりします。

  4. モデル(どの AI を使うか)を「Sonnet」にする

    Claude にはいくつかの種類(モデル)があり、賢さ・速さ・利用料金が違います。入力欄の左下に表示されているモデル名(例: 「Opus 5.5 Medium」)をクリックすると、モデルを選ぶメニューが開きます。

    この演習では「Sonnet」を選んでください。Webアプリ作りには十分な性能があり、使った分の料金(画面の「$2/$10 per Mtok」の部分)が Opus の半分で済みます。

    Sonnetこの演習ではこれを使います。普段の作業に向いた、性能と料金のバランスがよいモデル。
    Default / OpusSonnet より高性能ですが、料金が高めです。Sonnet で何度頼んでもうまくいかないときだけ、試しに切り替えてみます。
    Fable最も高性能で、料金も最も高いモデル。この演習では使わないでください。
    Haiku最も速く安いモデル。簡単な質問には向きますが、アプリ作りには力不足なことがあります。
    選んだモデルは入力欄の左下に表示されます。新しい会話を始めたときなどに Sonnet 以外に戻っていたら、選び直してください。「Effort」や「Ultracode」は変更せず、そのままにしておきます。

  5. モード(どこまで自動で作業させるか)を確認する

    ログインするとチャット画面になります。入力欄の右下にあるモードの表示(例: 「Edit automatically」)をクリックすると、 Claude にどこまで自動で作業させるかを選べます。Shift+Tab でも切り替えられます。

    Manualファイルを編集するたびに許可を求めてくる。何をしているか1つずつ確かめたいときに。
    Edit automaticallyファイルの編集は自動で行う。この演習ではこれがおすすめです。
    Planすぐに編集せず、まず計画を説明してくれる。大きな変更の前に。
    Auto安全チェックを通った操作は自動で許可し、危なそうなものだけ止まって確認する。
    Bypass permissions危険なコマンドも確認なしで実行する。初期設定では表示されないこともあります。表示されていても、この演習では使わないでください。

    「Edit automatically」でも、プログラムの実行などファイル編集以外の操作をするときは、Claude が「実行してよいですか?」と確認してきます。 内容を読んで問題なければ Yes を選んで承認します(キーボードの y でも承認できます)。 よく分からないときは承認せずに、「これは何をするコマンドですか?」と聞いてかまいません。

    メニュー下部の「Effort」「Ultracode」は変更せず、そのままにしておきます。最初に出る「Learn Claude Code」のパネルは、右上の × で閉じてかまいません。

  6. 使える状態か確認する

    チャット欄に次のように入力して送信します。返事が返ってくれば準備完了です。

    こんにちは。あなたは何ができますか?初心者向けに短く教えてください。

  7. 英語で返ってきたら、日本語で答えるよう頼む

    日本語で質問しても、最初は英語で回答してくることがあります。そのときは慌てずに、日本語で答えるように頼みましょう。

    これからは日本語で回答してください。

    途中でまた英語に戻ったときも、同じように頼めば日本語に戻ります。

  8. Claude Code に最初の指示を出す

    Claude Code を開き、作りたいものを伝えます。最初は小さく・シンプルに頼むのがコツです。例:

    このフォルダに、ブラウザで遊べるシンプルな「もぐらたたき」ゲームを作ってください。index.html の1ファイルにまとめ、HTML・CSS・JavaScript はすべてこのファイルに入れてください。

    ほかの例:

    今日やることを追加・完了・削除できるToDoリストのWebアプリを index.html 1ファイルで作ってください。データはブラウザに保存して、再読み込みしても消えないようにしてください。
    日本の都道府県の県庁所在地を当てる4択クイズを index.html 1ファイルで作ってください。10問出題して最後に正解数を表示してください。

  9. 許可を求められたら内容を読んで答える

    Claude Code はコマンドを実行するときなどに、許可を求めてきます(どの操作で聞いてくるかは、この章で選んだモードによって変わります)。何をしようとしているかを読み、問題なければ許可します。 分からないときは許可せずに「これは何をするコマンドですか?」と質問してかまいません。

  10. ブラウザで動かす

    できあがった index.html をエクスプローラーでダブルクリックすると、ブラウザで開きます。Claude Code に頼んでもかまいません。

    index.html をブラウザで開いてください。

    実際に操作して、思ったとおりに動くか確かめましょう。

  11. 何が作られたか説明してもらう

    今作ったコードの構成と仕組みを、プログラミング初心者向けに説明してください。

伝わりやすい指示のコツ

何をどんなアプリか(ゲーム、ToDo、クイズ…)
どんな画面・動きボタンの配置、色の雰囲気、クリックしたら何が起きるか
ファイル構成「index.html の1ファイルで」など。最初は1ファイルが分かりやすい
条件・制約「スマホでも見やすく」「外部のライブラリは使わない」など

3AIと対話しながら改良する

動くものができたら、遊んでみて気づいたことを伝え、少しずつ改良します。1回に頼むことは1つか2つにして、そのたびに動作を確認するのがコツです。

  1. 機能を追加する

    スコアが10点上がるごとに、もぐらが出てくる速さを少しずつ上げてください。
    ゲーム終了時に、これまでの最高得点も表示されるようにしてください。

  2. 画面のデザインを変える

    全体をやわらかいパステルカラーにして、ボタンを角丸で大きくしてください。スマホの画面幅でも見やすいレイアウトにしてください。

  3. バグを直す

    「何をしたら」「何が起きたか」「本当はどうなってほしいか」の3点を伝えます。

    スタートボタンを2回続けて押すと、もぐらが2倍の速さで出てきてしまいます。ゲーム中はスタートボタンを押せないようにしてください。

思いどおりに動かなかったときの対処方法

  1. 症状を具体的に伝える

    「動きません」だけでは AI も原因を絞れません。どの操作で、どうなったかを書きましょう。

  2. エラーメッセージを見せる

    ブラウザで F12 を押して開発者ツールを開き、Console(コンソール)タブに赤い文字が出ていたら、コピーして Claude Code に貼り付けます。

    ボタンを押しても何も起きません。ブラウザのコンソールに次のエラーが出ています: (ここにエラーを貼り付け)

  3. 画面のスクリーンショットを見せる

    表示の崩れなど言葉で説明しにくいときは、スクリーンショットを撮って(Windows は Win+Shift+S)チャット欄に貼り付けると伝わりやすくなります。

  4. 再読み込みを忘れない

    修正したのに変わらないときは、ブラウザで Ctrl+F5(Mac は Cmd+Shift+R)を押して再読み込みしてみましょう。

  5. 原因を一緒に調べてもらう

    同じ不具合が直りません。考えられる原因の候補を挙げて、1つずつ確認しながら直してください。

  6. 悪くなったら元に戻す

    修正でかえって悪くなったら、元に戻すよう頼めます。うまく動いている段階でフォルダごとコピーしてバックアップしておくと安心です。

    さっきの変更で、かえって動かなくなりました。直前の変更を元に戻してください。

  7. 会話をリセットする

    やりとりが長くなって話がかみ合わなくなったら、新しい会話を始め、今のアプリの状態と次にやりたいことを改めて説明すると、うまくいくことがあります。

4GitHub Pagesで公開する 発展課題

作ったアプリをインターネットに公開し、URL を知っている人なら誰でもスマホやPCから遊べるようにします。

公開すると誰でも見られます。名前・学籍番号・パスワードなどの個人情報や、他人の画像・音楽などを含めないでください。

  1. GitHub アカウントを作る

    github.com で「Sign up」からアカウントを作成します。ユーザー名は公開URLの一部になります。

  2. GitHub にリポジトリ(保存場所)を作る

    GitHub にログインし、画面右上の「+」→「New repository」を選びます。

    「Create a new repository」の画面で、次のように入力して「Create repository」を押します。

    Repository name作業フォルダと同じ名前(例: my-first-app)。「is available.」と緑で出れば使える名前です。
    Choose visibilityPublic(無料プランで GitHub Pages を使うには Public が必要です)
    Add README などOff / No .gitignore / No license のままにします。空のリポジトリにしておくと、手元のファイルをそのまま送れます。

  3. Git が使えるか確認する(なければ入れてもらう)

    Git はファイルの変更履歴を記録するツールで、GitHub にファイルを送るときに使います。Claude Code に確認してもらいましょう。

    このPCに git がインストールされているか確認してください。入っていなければインストールしてください。

    入っていない場合、Claude Code がインストール方法を選択肢で質問してくることがあります。おすすめ(Recommended)を選んで「Submit answers」を押せば、Claude が入れてくれます。 途中で Windows の「このアプリがデバイスに変更を加えることを許可しますか?」という確認が出たら「はい」を押します。

  4. リポジトリに push する

    作ったファイルを GitHub に送ります(push)。Claude Code に頼みましょう。

    このフォルダを git で管理して、GitHub の https://github.com/ユーザー名/リポジトリ名 に push してください。初めてなので、各手順で何をしているか説明しながら進めてください。
    「ユーザー名」は自分の GitHub のユーザー名に、「リポジトリ名」は手順2で付けた名前(自分の作業フォルダの名前。例: my-first-app)に置き換えてから送ってください。 リポジトリのページを開いたときのブラウザのアドレス欄の URL をコピーして使うと確実です。

    Claude Code は次のような順番で作業します。説明を読みながら、聞かれたことに答えていきましょう。

    1. 名前とメールアドレスの設定: 変更の記録(コミット)に残る作者情報です。Public のリポジトリでは誰でも見られるので、メールアドレスには下の「GitHub の非公開用アドレス」を使うのがおすすめです。
    2. git init: このフォルダを Git で管理し始めます。
    3. コミット: 今のファイルを最初の記録として保存します。
    4. push: 記録を GitHub に送ります。
    GitHub の非公開用アドレス(noreply アドレス)の調べ方

    GitHub が用意している、本当のメールアドレスの代わりにコミットに載せられるアドレスです。このアドレスを使えば、メイジメールなどを公開せずに、GitHub 上では自分のコミットとして扱われます。

    1. GitHub の右上の自分のアイコン → Settings → 左側メニューの Emails を開きます。
    2. 「Keep my email addresses private」にチェックを入れます。
    3. その説明文の中に表示される 数字+ユーザー名@users.noreply.github.com の形のアドレスをコピーします。

    Claude Code に名前とメールアドレスを聞かれたら、次のように答えます。

    名前はユーザー名、メールアドレスは GitHub の非公開用アドレス(ここにコピーしたアドレスを貼り付け)を使ってください。

  5. GitHub へのログインを許可する

    初めて push するときは、GitHub へのログインを求められます。「Connect to GitHub」という画面が出たら「Sign in with your browser」を押し、 ブラウザで自分の GitHub アカウントにログインします。「Authorize Git Credential Manager」と表示されたら、緑の「Authorize git-ecosystem」を押して許可します。

    許可は1回だけで、次からは自動でログインされます。Claude Code が「main -> main」のような結果を表示すれば push 成功です。

    Claude Code が「ログイン画面を表示できないので push できない」と言ってきたら、次のように頼んでみましょう。それでも出ないときは、VS Code のターミナル → 新しいターミナルで git push -u origin main を自分で実行します。
    GitHub のログイン画面が表示されるようにして、もう一度 push してください。

  6. GitHub Pages を有効にする

    GitHub のリポジトリのページを開き、上のタブの「Settings」→ 左側メニューの「Pages」を開きます。 「Build and deployment」の Source が Deploy from a branch になっていることを確認します。

    最初は Branch が「None」(Pages が無効)になっています。「None」をクリックして main を選ぶと、右にフォルダ /(root) が表示されます。そのまま「Save」を押します。

    下にある「Visibility」(GitHub Enterprise)や「Start free for 30 days」は有料プラン向けの機能です。押さなくてかまいません。

  7. 公開されたページを開く

    数分待つと、次のURLで公開されます。Settings → Pages の画面を再読み込みすると、上部に公開URLが表示されます。index.html がトップページになります。

    https://ユーザー名.github.io/リポジトリ名/

    太字の部分は自分のものに置き換わります。例えばユーザー名が meiji-taro、リポジトリ名が my-first-app なら https://meiji-taro.github.io/my-first-app/ です。

    リポジトリの中のフォルダにある index.html は、…/リポジトリ名/フォルダ名/ のように URL の後ろにフォルダ名を付けると開けます。

  8. 更新する

    アプリを改良したら、変更を GitHub に送ります。数分で公開ページにも反映されます。

    今の変更をコミットして GitHub に push してください。公開アドレスをブラウザで開いてください。
注意点・うまくいかないとき
  • GitHub Pages で公開できるのは HTML・CSS・JavaScript などのファイルだけです。Python などで動かすサーバーの機能は、GitHub Pages 上では動きません。作例の game は、対局記録を保存するために別のサービス(Google Apps Script)を使っています。サーバーの機能も公開したい場合は、下の「サーバーの機能も公開したいとき」を見てください。
  • ページが表示されない(404 になる)ときは、数分待ってから再読み込みしてください。リポジトリの Actions タブで公開処理の状況を確認できます。
  • Git をインストールした直後は、すでに開いていたターミナルでは git が見つからないことがあります。新しいターミナルを開くか、VS Code を再起動してください。
  • push でエラーが出たら、表示されたメッセージをそのまま Claude Code に伝えて「どうすればよいですか?」と聞きましょう。
サーバーの機能も公開したいとき(GitHub Pages 以外の選択肢)

データをサーバーに保存したい、Python のプログラムを動かしたい、といった場合は、プログラムを動かせる公開サービスを使います。代表的なものは次のとおりです。 どれも GitHub のリポジトリと連携でき、push すると自動で公開し直されます。

VercelWebページに加えて、JavaScript や Python で書いた小さなサーバー処理(サーバーレス関数)を動かせます。 ただしサーバー上のファイルにデータを保存し続けることはできないので、データベースや Dropbox などの外部の保存サービスと組み合わせます。
RenderPython などで書いたサーバーのプログラムを、ほぼそのまま動かせます。無料プランでは、しばらくアクセスがないと停止し、次に開いたときの起動に時間がかかります。
PythonAnywherePython に特化したサービスで、ファイルへの保存もできます。プログラムを Flask などの決まった形に合わせる必要があります。

このアプリはサーバーに記録を保存する機能があります。無料で公開するには、どのサービスを使ってどう直せばよいか、初心者向けに選択肢と手順を教えてください。
サーバーの機能を公開すると、世界中から誰でもアクセスできます。パスワードや API キーをプログラムに直接書かない、入力を何でも保存しないなど、安全面にも注意が必要です。不安なときは教員に相談してください。

5アプリ一覧に登録しよう 発展課題

4章で公開したアプリの URL を、演習の「みんなのWebアプリ一覧」ページに登録して、ほかの人にも遊んでもらいましょう。

みんなのWebアプリ一覧を開く ↗

  1. 自分のアプリの公開 URL を確認する

    4章の手順7で開いた公開ページ(https://ユーザー名.github.io/リポジトリ名/)をブラウザで開き、アドレス欄の URL をコピーします。 ほかの人の PC やスマホからでも開けるか、確かめておくと安心です。

  2. アプリのスクリーンショットを撮る

    一覧に表示する画像として、アプリの画面のスクリーンショットを撮ります。Windows では Win+Shift+S を押し、アプリの画面を範囲選択して撮ります (Mac は Cmd+Shift+4)。撮った画像はクリップボードに入るので、次の手順でそのまま貼り付けられます。

    アプリの楽しさが伝わる場面を撮りましょう。個人情報やほかのウィンドウが写り込まないように注意してください。

  3. 一覧ページから登録する

    アプリ一覧ページの「＋ 自分のアプリを登録する」を押すと、ページの中に登録欄が開きます。次の内容を入力して「登録する」を押します。

    作成者(ニックネーム)作者として表示される名前
    アプリ名一覧に表示される名前(例: もぐらたたき)
    アプリの URL手順1でコピーした公開 URL を貼り付け
    スクリーンショット手順2で撮った画像。登録欄の中で Ctrl+V を押すと貼り付けられます(画像ファイルを選んだり、ドラッグしたりしても登録できます)。画像は自動で小さく縮められます。
    一覧は誰でも見られます。本名や学籍番号は書かず、ニックネームを使ってください。

  4. 一覧に表示されたか確認する

    「登録しました!」と表示されると、登録欄が閉じて一覧が読み込み直され、自分のアプリが先頭に表示されます。タイルを押して、自分のアプリが開くか確かめましょう。

    内容を直したいときは、同じ URL でもう一度登録すると、新しい内容に置き換わります。

  5. ほかの人のアプリで遊んでみる

    一覧のアプリを開いて遊んでみましょう。よかったところや気づいたことを作者に伝えると、次の改良のヒントになります。 自分のアプリに取り入れたいアイデアがあれば、Claude Code に頼んで試してみましょう。
